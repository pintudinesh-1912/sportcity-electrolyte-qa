Collection Description
Electrolyte API test suite for the SportCity QA assessment (Part 1). **Run order matters.** Folders run top to bottom against a **freshly started** mock (restart it to reset seeded data): read-only checks first, then purchases, bookings and idempotency. Later requests read baselines saved by earlier ones (plan prices, spots per class). **Priority legend** - **P0** money, booking eligibility, or data the member sees directly. Release blocker if failing. - **P1** contract, validation and consistency. Should fix before release. - **P2** robustness and error-contract polish. Fix when convenient. **Source of truth.** Expected values for members, schedules and capacity come from the Perfect Gym screens in the kit (PG is the CRM of record). Assertions encode the *intended* behaviour from `openapi.yaml` and the acceptance criteria, so failing tests are findings, not test bugs. **Evidence on failure.** Every assertion runs through a `check()` wrapper. When one fails, the full API exchange is appended to its failure message: method + URL, query and path params, request headers (API key masked), request body, status, timing, response headers and response body (truncated at 4000 chars). This shows in the Newman CLI, the htmlextra *Failures* tab and the JUnit XML. Passing requests keep the standard htmlextra request/response view. Run with Newman: `./part1-test-design/run-newman.sh`
